# Security foundations, attacks & malware|1–2|Classify threats and connect common attack patterns to defenses.
+ Apply confidentiality, integrity, and availability to a local organization.
+ Distinguish threats, vulnerabilities, risks, and common attack techniques.
+ Compare malware defenses and use evidence when reviewing a public incident.
> CIA and risk|Confidentiality restricts disclosure, integrity preserves accuracy, and availability keeps services accessible.|An asset has value, a threat can harm it, and a vulnerability is an exploitable weakness. > Security roles and authorization|A SOC analyst triages alerts, an engineer builds controls, and an auditor checks evidence. Confirm the actual scope and written authorization.|A consultant authorized to assess a training server has no implied permission to test its payment provider.
> Attack patterns|Social engineering manipulates people. DDoS floods a service with traffic or requests. SQL injection changes the intended database query when input is handled unsafely.|Layer defenses: verification channels, traffic controls, parameterized queries, and monitoring.|A fake urgent portal notice exploits trust. > Malware and spyware|Ransomware can encrypt or disrupt access. Spyware collects information. A trojan disguises its purpose.|Update software, limit privileges, monitor endpoints, and plan recovery. Compare capabilities across anti-malware products.|On a managed device, a suspicious executable alert prompts IT to inspect logs and containment options.
> Incident evidence|Read advisories or confirmed reports. Separate affected assets, known facts, suspected causes, and recommended controls.|Avoid attributing an attack from an alert alone. # Web, cloud & IoT security|6|Explain common web flaws and check shared responsibility and device boundaries.
+ Explain HTTPS, TLS, and cookie attributes.
+ Distinguish SQL injection from cross-site scripting and identify preventive controls.
+ Assess a cloud storage and IoT scenario using an ownership matrix.
> Transport and cookies|HTTPS uses TLS to protect data in transit and verify the server identity through certificates.|Secure limits cookies to secure transport, HttpOnly blocks typical script access, and SameSite influences cross-site cookie sending.|A login cookie can use Secure and HttpOnly plus a SameSite setting compatible with the application's flows.
> SQL injection|Injection occurs when untrusted input becomes part of a database command. Parameterized queries keep values separate from SQL syntax.|Also limit database privileges and handle errors safely. Use trainer-provided examples instead of testing public sites.|A mock search handler passes a query and a separate search parameter to the database.
> Cross-site scripting|XSS can occur when a site includes untrusted data in a browser context that treats it as executable content.|Prefer safe rendering APIs, contextual output encoding, and sanitization where rich HTML is deliberately allowed.|Render a display name as text in a sample page rather than assigning it as HTML.
> Cloud responsibility|Cloud providers and customers have different responsibilities depending on the service. The customer commonly owns data classification, IAM, and settings.|Check public access, roles, logging, and recovery in the chosen service.|A cloud provider operates storage infrastructure while the customer configures who can read the objects.
> IoT inventory and isolation|List devices, owner, firmware, network, and support status. Change default credentials and restrict unnecessary access.|Segment cameras and sensors from ordinary staff systems where possible. Plan for unsupported devices.|A demo camera stays on its own segment with access limited to the monitoring workstation.
